# MMDモデル (PMX / PMD / DirectX .x) インポート技術仕様書

> [!NOTE]
> 本詳細技術仕様書は、AI によって作成・整理されたドキュメントです。内容はソースコードおよび開発記録をもとに記述していますが、実際の動作と細部が異なる場合があります。

本ドキュメントは、「MMD Tools for Maya」における MMD モデル形式（PMX 2.0/2.1、PMD、DirectX .x）のバイナリ・テキスト解析から、Maya 上でのポリゴンメッシュ生成、リグ（スケルトン・IK）、スキニング、モーフ、シェーディング、剛体・ジョイントの構築に至る詳細な技術仕様を定めたものです。

## 1. モデルファイルフォーマット解析仕様

### 1-1. PMX 2.0 / 2.1 解析仕様 (`mmd_core/pmx.py`)

PMX は MMD の現代的な標準モデル形式であり、ヘッダーにエンコーディングやインデックスサイズを定義するグローバル設定テーブルを持っています。

- **シグネチャ**: `PMX `（4バイト）
- **バージョン**: `2.0` または `2.1`
- **グローバル設定配列 (8バイト)**:
  - エンコーディング: 0（UTF-16LE）または 1（UTF-8）
  - 追加UV数: 0〜4
  - 頂点インデックスサイズ: 1, 2, 4 バイト
  - テクスチャインデックスサイズ: 1, 2, 4 バイト
  - 材質インデックスサイズ: 1, 2, 4 バイト
  - ボーンインデックスサイズ: 1, 2, 4 バイト
  - モーフインデックスサイズ: 1, 2, 4 バイト
  - 剛体インデックスサイズ: 1, 2, 4 バイト
- **頂点データ**:
  - 位置座標（`x, y, z`）: MMD 右手系（Z値の反転処理を適用して Maya 右手系へ変換）
  - 法線（`nx, ny, nz`）
  - テクスチャUV（`u, v`）: MMD では V=0 が画像上端、Maya では V=0 が画像下端となるため `1.0 - v` 反転を実施
  - ウェイト変形方式: BDEF1（単一骨）、BDEF2（2骨線形補間）、BDEF4（4骨線形補間）、SDEF（球形デュアルクォータニオン）、QDEF（デュアルクォータニオン）
- **材質データ**:
  - 拡散色（RGBA）、鏡面反射色（RGB・光沢度）、環境光色（RGB）
  - 描画フラグ: 両面描画、地面影、セルフシャドウマップ、セルフシャドウ描画、輪郭線描画
  - テクスチャインデックス、スフィアテクスチャインデックス（乗算/加算/サブテクスチャ）
  - 共有Toonフラグ（0: 個別テクスチャ, 1: 共有toon01.bmp〜toon10.bmp）
- **ボーンデータ**:
  - ボーン和名、ボーン英名、位置座標（`x, y, z`）、親ボーンインデックス、変形階層
  - ボーンフラグ: 接続先（座標/ボーン）、回転可能、移動可能、表示、操作可能、IK、付与親回転/移動、軸固定、ローカル軸、変形後変形、外部親変形
- **モーフデータ**:
  - 頂点モーフ、UVモーフ、ボーンモーフ、材質モーフ、グループモーフ
- **剛体データ**:
  - 剛体和名、剛体英名、関連ボーン、衝突グループ、非衝突グループマスク、形状（球/箱/カプセル）、サイズ、位置、回転、質量、減衰、反発、摩擦、剛体タイプ（0: Kinematic, 1: Dynamic, 2: Aligned）
- **ジョイントデータ**:
  - ジョイント和名、ジョイント英名、接続剛体A、接続剛体B、位置、回転、位置制限（下限/上限）、回転制限（下限/上限）、ばね定数（位置/回転）

### 堅牢化PMXバイナリパーサー仕様 (`mmd_core/pmx.py`)

国内外の多様な配布モデルや破損リスクのあるPMXファイルであっても、読み込みエラーによるクラッシュを起こさず安全にロードを完了するための堅牢化仕様です。

- **多重文字エンコードフォールバック**:
  - ヘッダーで指定されたエンコードフラグ（UTF-16LE / UTF-8）に加え、フラグ偽装や不正バイト列を含むファイルに対して CP932（Shift_JIS）、GBK、EUC-JP の多段階フォールバックを自動試行。
  - 不明な不正バイトシーケンスは安全な代替文字へ置換し、デコード失敗による中断を防止。
- **ストリームリーダーの安全終端パディング**:
  - ファイル末尾が途切れた欠損PMXやデータ境界超過時、例外でクラッシュさせずにゼロパディングされた安全なダミーバイト列を返却して終端を保護。
  - float値に含まれる非数値（NaN）や無限大（Inf）を自動検出し、0.0 へ安全クランプ。
- **頂点ウェイト・インデックスの自動修復**:
  - 各頂点のボーンウェイト合計が 0 または NaN になっている不良頂点を検出した場合、第1ボーンへウェイト 1.0 を自動割り当てしてメッシュ形状崩壊やスキニング計算例外を防止。
  - ボーンインデックスや材質インデックスの範囲外参照を上限値・下限値へ安全クランプ。
- **不正モーフオフセットの自動除外**:
  - モデル内の存在しない頂点インデックスやボーンインデックスを参照している不正なモーフオフセット定義を自動検出し、不正な要素のみを除外してモデル全体の正常なインポートを継続。

### 1-2. PMD 解析および PMX 変換仕様 (`mmd_core/pmd.py` / `converters/pmd2pmx.py`)

PMD は MMD の旧標準バイナリ形式です。最新の PMX 形式への移行を促すため、インポート時の自動変換機能およびスタンドアロン変換ツールを提供しています。

- **文字エンコード**: Shift_JIS 固定（多重文字コード自動フォールバック対応）
- **解析と統合**:
  - `load2pmx` 関数により、PMD バイナリデータを解析して PMX 互換のデータ構造体へと変換。
  - ボーン定義直後の IK セクション（IKターゲット、チェーン数、ループ回数、制限角度）を解析し、PMX の IK 構造へマッピング。
  - 材質の Toon インデックス（0〜9）を共有 Toon テクスチャ番号に変換。
  - スフィアマップ指定（`tex*sph` / `tex*spa`）を自動検出し、乗算モード（Mode 1）および加算モード（Mode 2）へ正確に分離・登録。
- **PMD 拡張セクション（剛体・ジョイント）の解析対応**:
  - PMD フォーマットの拡張セクションに記録された英語情報、Toonテクスチャ名、剛体（RigidBody: 83バイト単位）およびジョイント（Joint: 124バイト単位）のバイナリを抽出。
  - PMD モデルに付属する物理パラメータを保持した状態で PMX 構造体へ変換します。
- **PMD → PMX 変換エンジン (`converters/pmd2pmx.py`)**:
  - `convert_pmd_to_pmx(pmd_path, pmx_path=None)`:
    PMD ファイルを解析し、同一フォルダ内に `<モデル名>.pmx` として保存。
- **インポート時の非推奨検出と対話型自動変換**:
  - GUI 上で `.pmd` ファイルを選択してインポートを実行した際、確認ダイアログを表示。
  - ユーザーが「はい」を選択すると即座に同一フォルダへ `.pmx` を生成し、入力ファイルパスを自動更新した上で、未登録漢字チェックや剛体・Joint可視化生成を含む高機能な PMX インポートパイプラインを継続実行。
  - 「いいえ」を選択した場合は従来の PMD 読み込みを継続し、「キャンセル」を選択した場合は処理を中断。
- **その他機能タブのスタンドアロン変換機能**:
  - その他機能タブの共通設定グループ内に「PMD → PMX に変換」ボタンを配置し、モデルインポートを行わずに指定したPMDファイルをPMXへ変換・保存する単独ツールとして提供。

### 1-3. DirectX .x ファイル構文解析仕様 (`mmd_core/x_file.py`)

DirectX 形式のモデル・アクセサリファイル（テキスト形式およびバイナリ形式）に対応しています。

- **字句解析器（Tokenizer）**:
  - `template Mesh { ... }` などの DirectX 標準テンプレート定義ブロックを自動的にスキップ。
  - 不規則な改行、コメント（`//` や `#`）、セミコロン・カンマなどの区切り文字を正規化してトークンストリームを生成。
- **データ抽出**:
  - `Mesh` ブロック内の頂点座標、面インデックス（3角形・4角形の自動3角形分割）。
  - `MeshNormals`（法線ベクター）、`MeshTextureCoords`（UV座標）。
  - `MeshMaterialList`（材質カラー、テクスチャファイル名パス）。

## 2. Maya シーン構築アーキテクチャ (`pmxpaimaya.py`)

### 2-1. メッシュ高速生成 (`MFnMesh.create`)

Maya API 2.0（`maya.api.OpenMaya.MFnMesh`）を利用し、Python ループによる個別頂点設定を排除して一括配列渡しにより数十万ポリゴンのモデルを数秒で構築します。

- 頂点配列: `MPointArray`
- 面ポリゴン頂点数配列: `MIntArray`
- 面頂点接続インデックス配列: `MIntArray`
- UV座標配列: `MFloatArray`（U値および `1.0 - V` 反転値）
- 面へのシェーダーグループ割り当て: `MObjectArray` による材質別マテリアル割り当て

### 2-2. スケルトン（ジョイント階層）の生成

- MMD のボーン座標系を Maya 座標系へ変換（X, Y, -Z）。
- ルートボーンから親ボーンインデックスに基づいて親子階層を再帰的に構築。
- ボーン名には安全変換（`jaka.py` によるローマ字変換）を施しつつ、元の日本語名および英語名を Maya ノード属性（カスタムアトリビュート）およびメタデータに永続化。

### 2-3. スキニング（SkinCluster）の適用

- Maya の `skinCluster` コマンドを使用。
- BDEF1, BDEF2, BDEF4 のウェイト情報を Maya API の `MFnSkinCluster.setWeights` を用いて一括書き込み。
- SDEF 頂点に関しては、Maya 上での実用性を重視し、デュアルクォータニオン近似または線形ブレンドウェイトへ正規化して割り当て。

### 2-4. 足IKリグの自動構築 (`setup_mmd_ik`)

MMD の標準的な足構造（足 → ひざ → 足首 → つま先）に対して、Maya 標準の IK ソルバーを自動生成します。

- **足首IK**:
  - ソルバー: `ikRPsolver`（回転面ソルバー）
  - スタートジョイント: 左足/右足（太もも）
  - エンドエフェクター: 左足首/右足首
  - 連動: 作成された IK ハンドルを「左足ＩＫ」ボーンの子階層にペアレント化。
- **つま先IK**:
  - ソルバー: `ikSCsolver`（単一チェーンソルバー）
  - スタートジョイント: 左足首/右足首
  - エンドエフェクター: 左つま先/右つま先
  - 連動: 「左つま先ＩＫ」ボーンに追従するように接続。

### 2-5. モーフ（BlendShape）高速直接書き込み仕様 (Sparse Target Delta Direct Write)

従来のメッシュ複製ループ（`mc.duplicate` / `mc.delete`）による多大なメモリ割り当てとGCオーバーヘッドを全廃し、Maya API 2.0（`maya.api.OpenMaya`）を用いた「ブレンドシェイプターゲット差分直接書き込み方式」を実装しています。

- **空 BlendShape ノードの生成**:
  - ベースメッシュのみを引数として `mc.blendShape(model_mesh_node)` を呼び出し、余分なジオメトリを持たない空のブレンドシェイプノードを瞬時に生成。
- **プラグ探索とデータストリーム**:
  - `MFnDependencyNode` から `inputTarget[0].inputTargetGroup[m_idx].inputTargetItem[6000]` プラグを取得。
  - プラグの子属性から、頂点座標配列プラグ（`inputPointsTarget`）および移動対象コンポーネントリストプラグ（`inputComponentsTarget`）を特定。
- **スパース差分データ（Sparse Target Delta）の直接注入**:
  - 移動が発生する頂点インデックスのみを `MFnSingleIndexedComponent(kMeshVertComponent)` に登録。
  - 差分移動ベクトル（`dx * scale`, `dy * scale`, `-dz * scale`, 1.0）のみを `MPointArray` に構築。
  - `MFnPointArrayData` および `MFnComponentListData` を用いて、Maya 内部のデータスロットへ直接一括書き込み。
  - 100個以上の頂点モーフを持つ大規模モデルであっても、約3秒台で全モーフの構築が完了する高速性を達成。
- **正規エイリアス登録とUI・VMD整合性保証**:
  - 各モーフターゲットウェイト（`weight[m_idx]`）に対して、Maya内部およびUI表示で安全な正規エイリアス名 `temp_bs_{m_idx:03d}_{safe_morph_name}` を自動付与。
  - モデル構造辞書（`morph_structure_map`）に日本語名および英名とエイリアス属性名のマッピングを記録。
  - これにより、チャネルボックス、シェイプエディタ、表情操作UI（`morph_window.py`）、およびVMDインポートでの一貫したキーフレーム適用と相互運用性を維持。

## 3. MMD シェーディング & セルフ影再現アーキテクチャ

MMD 特有のセル調アニメ陰影（Toon）、MMD標準照明、セルフ影（なし／モード1／モード2）、金属光沢（スフィア）を、Maya の Viewport 2.0 上でリアルタイム再現するための技術仕様です。

### 3-1. MMD デフォルト照明の幾何学的再現仕様

MMD（MikuMikuDance）の初期照明設定を Maya 右手系（Y-up）へ幾何学的に忠実変換してディレクショナルライト（`MMD_Directional_Light`）を生成します。

- **照明カラーおよび強度（白飛び防止最適化）**:
  - MMD デフォルト値: 赤 154, 緑 154, 青 154
  - Maya RGB 正規化値: $(154 / 255, 154 / 255, 154 / 255) \approx (0.60392, 0.60392, 0.60392)$
  - 平行光強度: `intensity = 0.85`
  - 環境光設定: `intensity = 0.35`, `color = (0.50, 0.50, 0.50)`, `ambientShade = 0.15`
  - 直射光と環境光の合算照度を適正化し、強照度や白地テクスチャにおける露出オーバー（白飛び）を防止。
  - 材質のアンビエント色（`ambient`）が過大なモデルに対して上限 0.60 の安全クランプを実施。
- **照射方向ベクトルと Maya ライト回転角**:
  - MMD 座標系光線ベクトル: $\mathbf{V}_{\text{mmd}} = [-0.5, -1.0, 0.5]$（左・下・手前から照射）
  - Maya 右手系（Z反転）における光線進行方向: $\mathbf{V}_{\text{maya}} = [0.5, -1.0, 0.5]$
  - 正規化光線単位ベクトル:
    $$\mathbf{L} = \frac{[0.5, -1.0, 0.5]}{\sqrt{0.5^2 + (-1.0)^2 + 0.5^2}} = \left[\frac{1}{\sqrt{6}}, -\frac{2}{\sqrt{6}}, \frac{1}{\sqrt{6}}\right] \approx [0.40825, -0.81650, 0.40825]$$
  - Maya Directional Light のオイラー回転角（度数法）:
    $$\text{RotateX} = \arcsin\left(-\frac{2}{\sqrt{6}}\right) \times \frac{180}{\pi} \approx -54.7356^\circ$$
    $$\text{RotateY} = 45.0^\circ$$
    $$\text{RotateZ} = 0.0^\circ$$
  - この回転角により、Maya シーン上の影の落ち方が MMD 本家と 100% 一致します。

### 3-2. ワールド空間 (World Space) Toon シェーディング・ノードネットワーク

従来のビュー空間法線サンプリングでは、カメラ（視点）を動かすと影が追従して動いてしまう深刻な課題がありました。
本システムでは **ビュー空間法線を行列積によりワールド空間法線へと変換** し、固定光線ベクトルとの内積を算出することで、MMD と同様に「視点を動かしても影が固定される」ワールド空間シェーディングを実現しています。

```text
[samplerInfo.normalCamera (ビュー空間法線)] ─┐
                                             ├─> [vectorProduct (Op 3: Vector Matrix Product)] ─> [ワールド法線 N] ─┐
[samplerInfo.matrixEyeToWorld (ビュー→ワールド行列)] ┘                                                                 │
                                                                                                                      │
[固定光線ベクトル L: (0.40825, 0.81650, 0.40825)] ────────────────────────────────────────────────────────────────────┼─> [vectorProduct (Op 1: Dot Product)]
                                                                                                                      │
                                                                                                                      ▼
                                                                                                       [内積 N・L (-1.0 〜 1.0)]
                                                                                                                      │
                                                                                                                      ▼
                                                                                                       [setRange (リニア全域正規化)]
                                                                                                          oldMin=-1, oldMax=1
                                                                                                          min=0,     max=1
                                                                                                                      │
                                                                                                                      ▼
                                                                                                       [reverse (階調反転: 1.0 - V)]
                                                                                                                      │
                                                                                                                      ▼
                                                                                                       [place2dTexture.vCoordInput]
                                                                                                                      │
                                                                                                                      ▼
                                                                                                       [file (Toonテクスチャ)]
                                                                                                                      │
                                                                                                                      ▼
                                                                                                       [マテリアル (Lambert / StandardSurface)]
```

- **シャドウアクネ・等高線ノイズの防止**:
  - `setRange` ノードで入力範囲を `oldMinX = -1.0, oldMaxX = 1.0`、出力範囲を `minX = 0.0, maxX = 1.0` に設定し、MMD本来の滑らかなリニア全域グラデーションをサンプリング。
  - 階調の急変や不自然な境界線の発生を排除。

### 3-3. セルフ影 (Self-Shadow) 3段階モード仕様

MMD のインポート時および既存シーンにおいて、ユーザーは3種類の影描画モードを選択可能です。

| :--------------------------------- | :---------------: | :-----------------------: | :-------------------------------: | :-------------------: | :----------------------------------------------------------------------------------------------------------------------------------- |
| **セルフ影なし** (`shadow_mode=0`) |      **OFF**      |             -             |                 -                 |           -           | セルフシャドウ（落ち影）を無効化。**ただし Toon シェーディングの表面明暗（陰影）は維持**され、MMD本家の「セルフ影なし」と一致。      |
| **モード1** (`shadow_mode=1`)      |      **ON**       |           2048            |                 3                 |         0.015         | 適度なソフトシャドウ。バイアスを適正化し、顔や服のメッシュ表面に発生するシャドウアクネ（不自然な等高線縞模様）を徹底防止。標準推奨。 |

### 3-4. StandardSurface 質感制御 & ユーザー辞書連動マテリアル保護

Maya 2020 以降の標準物理ベースシェーダー（`standardSurface`）および Blinn/Phong/Lambert 使用時、MMD キャラクターの肌や顔、瞳に不要なスペキュラ反射（テカリ・ギラつき）が発生してアニメ調の見た目が崩れるのを防止するため、以下のプロパティ制御を実施します。

- **顔・肌・表情マテリアルの自動保護 & テカリ除去**:
  - `user_dict_manager` で管理される保護キーワード（デフォルト: `顔`, `head`, `face`, `目`, `eye`, `瞳`, `眉`, `brow`, `口`, `mouth`, `舌`, `歯`, `唇`, `lip`, `表情`, `頬`, `肌`, `skin`, `body`, `体`, `鼻` 等）に一致する材質を検出。
  - `specularRoughness = 0.5`（反射拡散）、`specularWeight = 0.0` / `specularColor = (0,0,0)`（ハイライト反射カット）を設定し、アニメ調のマットな美肌質感を保証。
- **Toon乗算除外（バイパス）仕様**:
  - 瞳のハイライトパーツ等（除外キーワード: `瞳-高光`, `高光`, `眼白`, `highlight`, `ハイライト` 等）は、Toonシェーディングによる暗化を行わず、テクスチャ本来の純白・高輝度をそのまま維持。
- **上級者向けGUIカスタマイズ**:
  - メニュー「MMD」 → 「高度なユーザー辞書・マテリアル設定 (上級者向け)...」から、これらのキーワードをユーザーが自由に閲覧・追加・編集可能。設定は `asset/user_dictionary.json` に永続化され、インポートおよび既存シーン修復時に即座に反映されます。

### 3-5. 既存シーン設定変更機能 (`fix_toon_shading_in_scene`)

- **役割**: すでにインポートされた既存シーンに対して、再インポートを行うことなく、GUI の「既存シーンのToonシェーディング設定変更」ボタンから影モードの切り替えおよび最新のワールド空間 Toon ノードネットワークへの修復を即座に実行。
- **処理内容**:
  1. シーン内の `MMD_Directional_Light` の `useDepthMapShadows`, `dmapResolution`, `dmapFilterSize`, `dmapBias` を選択モードの値に更新。
  2. シーン内の全 Toon テクスチャ接続ノードを走査し、カメラ空間の旧接続を `matrixEyeToWorld` 経由のワールド空間接続へと自動再配線。
  3. 各種マテリアルのスペキュラ属性を再調整。

### 3-6. スフィアマップ・ノードネットワーク

- **乗算スフィア (`.sph`)**:
  - カメラ空間の反射ベクトルを計算し、スフィア画像をサンプリング。
  - ディフューズテクスチャカラーと `MultiplyDivide` ノードで乗算合成。
- **加算スフィア (`.spa`)**:
  - サンプリングしたスフィア色を、ベースカラーに `PlusMinusAverage` ノードで加算合成し、ハイライト光沢を再現。

### 3-7. 不透明材質の保護と透過材質（首影・頬線・透過板）の適正描画仕様

モデル全体の透過深度ソート破綻（前後関係の逆転やチラつき）を防止しつつ、透過板ポリゴン（首影、頬線、チーク、涙など）を自然に描画するための適正化仕様です。

- **不透明材質の厳格な保護**:
  - 顔（T*顔）、髪（T*髪）、服、肌、帽子など本来不透明なメッシュについては、テクスチャ画像（PNG等）の余白に透明ピクセルが存在する場合でも、シェーダーの `transparency` を `(0.0, 0.0, 0.0)`（不透明）として維持。
  - Viewport 2.0 の不透明描画パスで確実にZバッファへの深度書き込みを行わせることで、前髪の隙間から後頭部が透ける現象やポリゴン抜けを根本から防止。
- **意図的な板ポリ透過パーツの選択的接続**:
  - まつげ、アイライン、ハイライト、涙など明確な透過キーワードを持つ材質のみに限定してテクスチャ透過を接続。
  - 基本アルファが 1.0 未満の半透明材質（羽など）は、材質アルファとテクスチャアルファの乗算ブレンドを適用。
- **Viewport 2.0 深度ピーリング（Depth Peeling）の自動設定**:
  - 近接・重なり合った薄い透過ポリゴンの前後チラつき（Z-fighting）や描画順破綻を防止するため、インポート完了時に Maya の `hardwareRenderingGlobals.transparencyAlgorithm` を 3（Depth Peeling）に自動設定。

### 3-8. MMD純正方式の材質モーフ（Material Morph）統合合成ネットワーク仕様

参照実装の計算方式に基づき、複数の材質モーフが同一材質に重なる場合や、1つのモーフが複数の材質を同時に操作する場合（MAT_OFF 複数）でも破綻なく動作する統合ノードネットワークを自動構築します。

- **mmdToonShader (ShaderFX / OGSFX) および標準マテリアルの差異吸収**:
  - Maya の標準マテリアル（Lambert / Blinn / StandardSurface）と Viewport 2.0 専用 OGSFX シェーダー（`mmdToonShader`）の内部アトリビュート差異を自動吸収してバインド。
  - 標準マテリアルでは `transparency`（RGB反転透過）および `color` / `baseColor` へ接続。
  - `mmdToonShader` では Viewport 2.0 の透過パス評価特性に適合させるため、逆転透過アトリビュート `transparencyR/G/B` とシェーダー内部の直接アルファアトリビュート `diffuseAlpha` の双方へクランプ済みアルファ出力を並列供給する二重透過制御を採用。
- **複数材質操作（MAT_OFF 複数: ドロワoff、帽子off等）の並列分配**:
  - 1つのモーフアトリビュートから、影響を受けるすべての材質の合成ネットワークへ並列接続。
  - 例として「ドロワoff」操作時には、下着材質を透明化して消去しつつ、素肌材質（肌3）および下着2材質を不透明化して出現させる連動制御を確立。
- **アルファ統合合成ネットワーク**:
  - 各材質の初期アルファに対し、作用するすべての加算モーフ（`op == 1`）を `multDoubleLinear` でモーフウェイトと積算し、`plusMinusAverage`（1D）で一括合算。
  - `clamp` ノードで 0.0 〜 1.0 に安全クランプし、透過テクスチャがある場合はテクスチャアルファと乗算合成した上で、`reverse` ノード経由で `transparency` に接続。
  - 初期透明材質（頬染め、ガーン、肌3、下着2等）については、アルファ出現時に拡散受光（`diffuse`）を滑らかに有効化し、非表示時の受光漏れや影の残存を遮断。
- **カラー統合合成ネットワーク**:
  - 各モーフの色加算（diffuse RGB加算）を `multiplyDivide` ノードで算出し、同一材質に作用するすべての加算項を `plusMinusAverage`（3D）ノードに集約。
  - メインテクスチャ出力または基本色に対して加算カラーを合成し、シェーダーの `color` 属性（`mmdToonShader` の場合は `color` および `diffuseColor`）へ接続。
  - これにより、「ガーン赤」と「ガーン青」を同時に動かした際にも互いを上書き切断せず、赤と青が加算合成されて紫色になるMMD純正通りの描画を実現。
- **Maya カスタムアトリビュートへのバインド**:
  - モデルの親メッシュノードへ `matmorph_<モーフ名>` アトリビュートを生成し、表情操作GUI（`morph_window.py`）のスライダーやタイムラインキーフレームから直感的に操作可能。

### 3-9. 顔透過メッシュ（チーク・涙等）の白枠線・影解消（受光遮断 `diffuse = 0.0` & シャドウ最適化）

ディレクショナルライトの「Emit Diffuse（拡散反射）」やシャドウ表示が有効なシーン環境において、顔の肌メッシュ表面に重ねられたチーク・涙・顔斜線などの透過板ポリゴンが不要な光や落ち影を拾い、通常時に白い枠線や薄黒い四角い影として浮き出てしまう現象を解消します。

- **受光遮断とシャドウ最適化**:
  - 対象となる顔透過マテリアルを検出し、ディフューズ反射（受光強度）を `0.0` に最適化。
  - 自己影や落ち影の投影・受光フラグを適正化し、通常（モーフ非適用時）は地肌と滑らかに馴染んで不可視となる状態を維持。

> [!WARNING]
> **【モデル依存に関する注意点】**:  
> 顔透過メッシュの白枠線や影の解消処理は、モデルのメッシュ分割構造、法線の向き、テクスチャの境界ピクセル仕様によっては、きれいに白枠線や影が消えなかったり、表示が不自然になる場合があります。

### 3-10. トゥーン受光のディレクショナルライト動的追従と2重受光黒沈み解消

- **ライト回転へのリアルタイム追従**:
  - トゥーンシェーディングの陰影計算において、固定ベクトルによるハードコードを排し、シーン内のディレクショナルライトのワールド変換行列（`worldMatrix[0]`）とノードネットワークを動的に接続。
  - ライトの向きを変更すると、トゥーンの影の落ち方がビューポート上で滑らかに追従。
- **陰影バランスの適正化**:
  - シェーダーの受光係数バランス（拡散反射 0.65、基本テクスチャ 0.85）を適正化し、過度な陰影乗算による肌や衣装の黒ずみ・黒沈みを防止。

### 3-11. MMD標準地面影（シャドウキャッチャー）生成仕様

MMD仕様に準拠した地面影プレーンを自動生成します。

- **シャドウキャッチャー平面構造**:
  - Y=0 平面に専用シェーダー（`useBackground`）を接続したメッシュプレーンを自動配置。
  - 平面シェイプに対して片面描画（`doubleSided = False`）および裏面非描画（`backfaceCulling = 3`）を設定。
  - 地面上（Y >= 0）からは影を自然に受け止めつつ、カメラを地面下（Y < 0、煽りアングル）に配置した際もプレーンが裏面からモデルを遮蔽せず、モデル全身が綺麗に見えるよう透過表示。
- **一括削除との連動**:
  - シーンクリーンアップ時のMMD全削除機能により、地面影プレーン・シェーダー・シェーディンググループも自動検出して一括削除。

## 4. 日英ボーン対応辞書と構造キャッシュ仕様

### 4-1. 標準ボーン日英辞書 (`asset/bone_dict.py`)

PMX エディタにおける和名・英名定義および標準ボーン日英対応表（mikudan, blender2pmxem, usausakokoko）に準拠した双方向変換辞書です。

  - 接頭辞 `ひだり` / `みぎ` やローマ字 `hidari` / `migi` も安全にフォールバック。

- `bone_details`:

- このキャッシュにより、後続の VMD モーション適用や XPBD 物理演算エンジンが 100% 確実にボーンを特定できます。

## 5. PMXモデル詳細解析・一括保存およびユーザー辞書対話登録連携

### 5-1. モデル構成要素の一括保存 (`pmx_analyzer.export_pmx_structure`)

インポート画面の「PMXモデル解析・データ一括保存」ボタン、またはモデルインポート実行時に自動連動し、PMXモデルの 5 大構成要素を抽出して `<モデル名>_pmx_analysis.json` に構造化保存します。

- **材質 (materials)**: 拡散色、鏡面色、環境色、エッジ設定、テクスチャ、スフィア、Toon、両面描画フラグ等。
- **ボーン (bones)**: 座標、親階層、IKパラメータ、付与親設定等。
- **モーフ (morphs)**: パネル種別、モーフ種類（頂点・ボーン・UV・材質）、オフセット数。
- **剛体 (rigid_bodies)**: 関連ボーン、衝突グループ、マスク、形状、質量、減衰、摩擦、物理モード等。
- **Joint (joints)**: 接続剛体A/B、位置、回転、移動・回転制限範囲、ばね定数等。

### 5-2. 未登録ボーン名検出と対話型ユーザー辞書登録フロー (`pmx_analyzer.check_and_prompt_user_dict`)

特殊衣装モデルに存在する、標準辞書未記載の漢字・ボーン名を自動走査します。

1. **確認プロンプト**:
   - 未登録漢字が検出された場合、`QMessageBox` でユーザーに「登録のないボーン名があります。ユーザー辞書に記録しますか？」と問いかけます。
2. **登録 GUI (`UserDictRegisterDialog`)**:
   - 「はい」を選択すると専用ダイアログが開き、未登録漢字の隣にある入力欄にローマ字（半角英数）を入力して「辞書に登録して再チェック」をクリックします。
3. **即時反映 & 再チェック（サイドチェック）**:
   - 入力内容が `asset/user_dictionary.json` に保存され、メモリ上の `jaka.MMD_KANJI_DICT` に即時反映されます。
   - 自動的に再スキャンが実行され、未登録が解消されたかを確認します。
4. **スルー処理**:
   - プロンプトで「いいえ」を選択した場合は、登録を行わずにそのまま処理を継続します。

## 7. PMD剛体変換仕様および透過素材モーフ制御仕様

### PMD剛体ワールド座標系への自動変換

- **座標系変換ロジック**:
  - PMDフォーマットにおける剛体位置は関連ボーンの原点を基準とする相対ローカルオフセットとして格納されています。
  - PMXフォーマットではワールド絶対座標が要求されるため、関連ボーンが存在する場合は対象ボーンのワールド座標に剛体オフセットを加算してワールド位置を算出し変換します。
  - これにより、頭髪・スカート・腕部などの剛体が足元（原点）に密集する不整合を根本解消します。
- **PMD材質アルファ異常値の自動補正**:
  - 一部のPMDモデルにおいてパーセンテージ表記等によりアルファ値が1.0を超過（例: 99.0 や 100.0）している場合、自動的に0.0〜1.0の正規化値へ補正してインポートします。

### 透過素材モーフ（PMX・PMD共通）の表示制御

- **基本カラーの保持**:
  - 初期透明モーフ材質（頬染め・ガーン・涙など初期アルファが0.05以下の材質）を判定する際、基本カラー（`diffuse_color`）を黒色で上書きせず材質本来の色情報を維持します。
- **多種シェーダーに対するアトリビュート接続の網羅**:
  - `mmdMaterial`、`standardSurface`、`blinn` などの各種マテリアルに対し、透過度・受光強度（`diffuse` / `base`）・カラー変化の接続ロジックを網羅します。
  - `mmdMaterial` においては `transparency` および `diffuseAlpha`、`diffuse` 属性へのモーフ接続を確立し、スライダー操作に伴う透過・受光の連動を実現します。
- **テクスチャ透過接続の最適化**:
  - BMPなどアルファチャンネルを持たない画像形式の場合、テクスチャの `outTransparency` をシェーダーへ強制接続せず、材質自体の半透明度を優先して適用します。
- **頂点モーフ型透過表現の表示保証**:
  - PMDモデルや一部PMXモデルにおいて、頭部内部から板ポリゴンを手前展開させる頂点モーフ型表現が存在する場合、材質モーフの有無を判別し、手前展開時に不透明または適切な透過度で正しく可視化されるよう初期設定を調整します。

### ドロワoff等独立メッシュ材質の黒沈み防止仕様

- **顔オーバーレイ板ポリゴンと独立本体メッシュの識別判定**:
  - 初期アルファが0.05以下で材質モーフの対象となる材質のうち、チーク・涙・顔斜線・照れなどの顔面重層パーツ（オーバーレイキーワード合致材質）のみを「顔オーバーレイ板ポリゴン」として特定。
  - 素肌（例: `T_肌3`）や下着（例: `T_下着2`）、靴（`T_靴1`）、靴下（`T_靴下1`）などの独立本体メッシュ材質を明確に区分。
- **環境光（ambientColor）および通常受光率の維持**:
  - 顔オーバーレイ板ポリゴンは受光漏れや白浮き枠線を防止するためアンビエント色・スペキュラ色をゼロに遮断。
  - 一方、素肌や衣装などの独立本体メッシュ材質はモデル本来の環境光色（例: 0.60）および標準受光係数（0.65）を維持。
  - これにより、「ドロワoff」や衣装off適用時、影領域（セルフシャドウや奥まった部位）に入っても通常肌と同一の明度・色調が保たれ、不自然な黒沈みが発生しない構造を実現。

### 表情モーフ操作ウィンドウのモーフ重複登録防止仕様

- **シーン探索アトリビュートキーの適正化**:
  - モデルノード上のカスタム材質モーフアトリビュート探索時、内部アトリビュート名のみを辞書キーに登録し、`niceName` による二重登録を排除。
  - アトリビュート特定時はモデルノード上の `niceName` を安全に逆引き照合。
- **登録済み名称（表示名）およびアトリビュート名の二重検証**:
  - JSON解析データからのパネル振り分け時、およびシーン内実在アトリビュートからのフォールバック登録時の双方において、表示名（`registered_names`）および対象アトリビュート（`registered_attrs`）の二重管理を実施。
  - 同一の表示名または同一アトリビュートを対象とするモーフが「その他」パネルや各表情カテゴリ内に複数重複して表示される現象を排除。

  - これにより Norton が未知の新規プログラムとして検知・隔離する CyberCapture 警告の発生を抑止し、安全かつ迅速な起動を実現。

### C#リアルタイム物理ベイクにおける開始フレーム先行セットと安定化仕様

- **C#ビューア側での開始フレーム取得**:
  - `physics_bake_cs`（`PhysicsSimulationBakeViewer`）において、指定された開始フレーム（`startFrame`）を取得。
- **安定化前の開始フレーム姿勢先行セット**:
  - 安定化（ウォームアップ）処理を実行するよりも前に、開始フレーム時点の姿勢（ボーンFK/IKおよび剛体トランスフォーム）をモデル・剛体に先行セット（`resetAllBodies: true`）。
  - ビューポート表示およびカメラ追従を開始フレームの姿勢へ更新。
- **開始フレーム姿勢保持での安定化と残留速度クリア**:
  - 開始フレームのポーズを保持した状態で安定化（物理シミュレーション）を実行。
  - 開始フレームが0以外の場合、初期バインド姿勢からの急激な変化による剛体発散やめり込みを防ぐため、最低30ステップ（1秒相当）の安定化を自動適用。
  - 安定化終了後に剛体の残留速度・角速度・外力をクリアし、静止状態からベイクを開始する仕組みを確立。

### 参照実装解析に基づく専用ライト・地面影・エッジ描画仕様
 
 - **MMD専用平行光源・環境光の適正化**:
   - 平行光源の照射角度を正面・斜め上から優しく照らす角度 `[-30.0, 30.0, 0.0]` へ最適化。モデル正面に十分な光を届け、地面影は左奥方向へ自然に伸びる配置を実現。
   - 光源色を `(0.6039, 0.6039, 0.6039)`、強度を `1.0` に設定し、白飛びを防止した適正露出を確保。
   - アンビエントライト（強度0.65、Color 0.70、ambientShade 0.05）を配置し、MMD特有の明るくふんわりとしたアニメ陰影を再現。
   - Mayaにおけるライト生成コマンド（`directionalLight`, `ambientLight`）が自動生成する親トランスフォーム名とシェイプ名の不整合（二重Shape名やリネームによる参照切れ）を回避するため、リネーム後に `mc.listRelatives(parent, shapes=True, fullPath=True)` で現在の実在シェイプノードを確実に再取得して操作する堅牢化処理を実装。
 - **キャラクターメッシュのセルフシャドウ黒潰れ防止仕様**:
   - Mayaのハードウェアシャドウ（デプスマップシャドウ）による、帽子・前髪・スカートからの黒い遮光影直撃を防止するため、キャラクターメッシュ（単一メッシュおよび材質分割メッシュ）自身の影受け属性（`receiveShadows`）を `0`（False）に設定。
   - 影を落とす属性（`castsShadows=True`）は維持されるため、地面影プレーンには美しい足元影が投影される。
   - 地面影プレーン（`mmd_ground_shadow_plane`）自身は影を受け止める必要があるため、`receiveShadows=True` を維持。
   - 一括最適化関数 `optimize_model_meshes_for_mmd_lighting()` を整備し、モデルインポート時、シェーディング再適用時（`fix_toon_shading_in_scene`）、およびモーションインポート完了時（`restore_viewport_lighting`）の各段階で影受け無効化を担保。
 - **地面影（Ground Shadow）プレーンのZファイティング防止**:
   - 参照実装の射影行列オフセット（0.1）に倣い、地面影プレーン（`useBackground`）のY位置を `0.05` にオフセット配置。地面グリッドとの重なりチラつきを解消。
 - **MMDエッジ（輪郭線）の描画品質向上**:
   - `mmd_material.fx` のエッジ用ラスタライザステート `SolidCullFront` に `DepthBias = 500; SlopeScaledDepthBias = 1.0f;` を導入。本体表面との深度競合による輪郭線の途切れ・チラつきを防止。
   - 頂点押し出し処理（`VS_Edge`）における法線正規化の安全ガードを追加し、ゼロ除算やNaNの発生を防止。

### 複数モデル順次インポート機能仕様

同一シーン内に複数のPMXモデルを共存・連携させる制作フローに対応するため、複数モデルのキュー登録および順次インポート機能を実装しています。

- **複数モデルリスト管理とドラッグ＆ドロップ登録**:
  - インポートUIにおいて複数のPMXファイルをファイル選択ダイアログまたはドラッグ＆ドロップで一括登録可能なリストウィジェットを提供。
  - 各モデルのファイルパス、モデル名、インポート対象ステータスを一覧管理。
- **独立ネームスペースとルートグループ階層の分離**:
  - 各モデルのジョイント階層、メッシュ、シェーダー、マテリアルノードに対して固有のプレフィックスや階層グループを割り当て、ノード名衝突を防止。
  - モデルごとに独立したトップグループノードを生成し、シーン内での位置調整や非表示・個別選択を容易化。
- **実行ログダイアログでの順次進行管理**:
  - 複数モデルの一括インポート実行時、実行ログダイアログ（`ExecutionLogDialog`）が各モデルの解析・チェック・メッシュ構築・スキンバインド・モーフ生成を順次追跡。
  - 各モデルの開始と完了、所要時間をリアルタイムにレポート。
