# MMD プロジェクトファイル (PMM) 解析・インポート技術仕様書

> [!NOTE]
> 本詳細技術仕様書は、AI によって作成・整理されたドキュメントです。内容はソースコードおよび開発記録をもとに記述していますが、実際の動作と細部が異なる場合があります。

本ドキュメントは、「MMD Tools for Maya」における MMD プロジェクト形式（.pmm）のバイナリ解析、モデル・カメラ・照明・アクセサリ・音声アセットの抽出、ファイルパス解決と実体照合、および Maya 上への一括インポート・アニメーション構築に至る詳細な技術仕様を定めたものです。

---

## 1. PMM ファイルフォーマット概要とバイナリ仕様 (`mmd_core/pmm.py`)

PMM (Polygon Movie Maker) は、MikuMikuDance (MMD) のプロジェクト全体（シーン配置、モデル、カメラ、照明、アクセサリ、背景、音声、キーフレーム）を保持するバイナリファイル形式です。

### 1-1. ファイルヘッダーとバージョン判定
- **シグネチャ (30バイト)**:
  - `Polygon Movie maker 0001` (V1 形式: 旧仕様)
  - `Polygon Movie maker 0002` (V2 形式: 現行標準仕様)
- **解像度と基本設定 (V2)**:
  - レンダリング出力幅 (uint32)
  - レンダリング出力高さ (uint32)
  - カメラ視野角 FOV (float32, 標準30.0度)

### 1-2. モデルセクションのバイナリ構造
PMM 内にはプロジェクトに読み込まれたモデルスロット情報が連続して記録されています。
空スロットやパースズレによるゴーストデータを排除するため、ヘッダー署名とデータ境界を精密に走査して有効なモデル情報を抽出します。

- **モデル基本情報**:
  - スロット番号 (int)
  - モデル名称 (Shift_JIS 文字列)
  - 英語名称 / ソース名称
  - モデルファイルパス (Shift_JIS 相対パスまたは絶対パス: `.pmx` / `.pmd`)
- **キーフレームトラック**:
  - ボーンキーフレーム配列: 各ボーンごとのフレーム番号、平行移動ベクトル `(tx, ty, tz)`、回転クォータニオン `(qx, qy, qz, qw)`、ベジェ補間曲線パラメータ
  - モーフ（表情）キーフレーム配列: モーフ名、フレーム番号、適用ウェイト値（0.0 〜 1.0）
  - IK制御キーフレーム配列: 各IKボーンのON/OFF状態および連動パラメータ
- **モーション/ポーズ自動判定**:
  - 複数フレームにわたるボーン・モーフのキーが存在する場合は「モーション（最大フレーム数 F）」として判定
  - 1フレームのみの場合は「ポーズデータ (1F)」として判定
  - キーが存在しない場合は「なし」として判定

### 1-3. カメラセクションのバイナリ構造
モデルセクション直後に配置されるカメラトラックは、初期キーフレームおよび追加のスパースキーフレーム配列で構成されます。

#### カメラキーフレーム構造体
MMD 本家および参照実装の内部バイナリ仕様に準拠し、レコード長はバージョンにより異なります。
- **V1 レコード長**: 70 バイト
- **V2 レコード長**: 78 バイト

```text
先頭からの配置:
[00-03] フレーム番号: uint32 (4バイト)
[04-07] 前キーインデックス: uint32 (4バイト)
[08-11] 次キーインデックス: uint32 (4バイト)
[12-15] 目標注視点距離 (distance): float32 (4バイト)
[16-27] 注視点位置 (eye): float32 x 3 [tx, ty, tz] (12バイト)
[28-39] オイラー回転角 (target): float32 x 3 [rx, ry, rz] (12バイト, ラジアン)
--- 以下 V2 のみ配置 (8バイト) ---
[40-43] 親モデルインデックス: int32 (4バイト, -1: なし)
[44-47] 親ボーンインデックス: int32 (4バイト, -1: なし)
----------------------------------
[48-71] 補間曲線パラメータ: uint8 x 24 (24バイト)
[72-72] パースペクティブ有効フラグ: uint8 (1バイト, 0: OFF / 1: ON)
[73-76] 視野角 FOV: uint32 (4バイト, 度数)
[77-77] 選択フラグ: uint8 (1バイト)
```

> [!IMPORTANT]
> 距離 `distance` の直後に格納されている12バイトは **注視点位置 (eye: tx, ty, tz)** であり、その後の12バイトが **オイラー回転角 (target: rx, ry, rz)** です。この順序に従って正しくアンパックすることで、MMDとMaya間でのカメラアニメーションの向きと注視点挙動が整合します。

### 1-4. 照明・アクセサリ・音声セクション
- **照明セクション**:
  - 平行光の方向ベクトル `(lx, ly, lz)`
  - ライトカラー `(lr, lg, lb)`
  - アンビエント（環境光）カラー
- **アクセサリセクション (`.x`)**:
  - アクセサリ名称、ファイルパス、親ボーン追従アタッチ情報、位置・回転・拡大率
- **音声セクション (`.wav`)**:
  - プロジェクトに読み込まれている BGM 音声ファイルのファイルパス

## 2. アセット照合およびパス解決エンジン

PMM ファイルに記録されているファイルパスは作成者の PC 環境依存の絶対パスや相対パスであるため、インポート先の環境に合わせて自動解決を行います。

### 2-1. パス解決アルゴリズム
1. **直接存在確認**: 記録パスがそのままローカル環境に存在するか確認。
2. **プロジェクト基準相対解決**: PMM ファイルの配置フォルダを起点として相対パスを展開。
3. **同階層・サブフォルダ探索**: PMM ファイルと同じフォルダや `model/`, `UserFile/` 等の代表的なサブディレクトリ内をファイル名ベースで探索。
4. **マルチバイト・大文字小文字の吸収**: Windows 環境での Shift_JIS エンコーディング差異やパス区切り文字の正規化（`\` と `/`）。

### 2-2. 実体ファイル（PMX/PMD）との突合照合
検出されたファイルに対して高速なヘッダー解析を実施し、PMM に記録されたモデル名や構成要素と突合します。
- **一致**: PMM 記録名とファイル内モデル名が一致
- **部分一致**: ファイル名は一致するがモデル名に差異がある場合
- **未検出**: ローカル PC 上にファイルが見つからない場合

### 2-3. 旧データ（過去の残骸データ）の自動判定
PMM 内でモデルの差し替えや再読み込みを行った際に残存する古い残骸スロットを自動検出します。
同種のアセット内で名称やファイルベース名が重複しており、一方が存在して他方が未検出である場合、未検出側を「旧データ」としてマークし、初期インポート選択から除外します。

## 3. UI仕様 (`ui/pmm_dialog.py`)

### 3-1. プロジェクト解析ダイアログ (`PmmAnalysisDialog`)
PMM ファイルのドラッグ＆ドロップまたはファイル選択により開く、2カラム構成の総合診断ウィンドウです。
- **左カラム**:
  - プロジェクト基本情報（バージョン、出力解像度、カメラ視野角、検出アセット数）
  - 詳細解析ログ表示ボックス（ログのコピー・クリア機能付き）
- **右カラム**:
  - 参照ファイル一覧テーブル（No, 種別, 名称, ファイル状態, モデル照合, モーション判定, 最大フレーム, 解決ファイルパス）
  - 種別フィルタ（すべて、モデル、アクセサリ、音声・メディア）
  - ファイル未検出アイテムの表示切り替えチェックボックス
  - 「解決パスをコピー」「エクスプローラーで開く」操作ボタン
  - 「インポート設定...」ボタン（モデル検出時に有効化）

### 3-2. モデル・アセット選択ダイアログ (`PmmModelImportSelectDialog`)
インポートを実行するモデルおよび BGM 音声を一覧から選択・設定するダイアログです。

## 4. Maya への一括インポート・連携パイプライン

### 4-1. モデルの組み立て
- **PMD 自動変換**: PMD 形式のモデルが選択された場合、内部で PMX へ自動変換を行ってからインポート。
- **メッシュ・リグ・シェーダー生成**:
  `pmxpaimaya.py` を呼び出し、ポリゴンメッシュ、ボーン（スケルトン）、ブレンドシェイプ、マテリアル、剛体・Joint を自動生成。
- **二重トランスフォーム防止**:
  グループ化の際、メッシュノードの `inheritsTransform` を無効化し、ボーン変形との二重加算を抑止。

### 4-2. モーションデータの順次書き込み
- **スライダーのリセット**: モーション書き込み前に Maya のタイムスライダーを 0 フレームへリセット。
- **ボーンモーション**: 回転（クォータニオン）および移動キーを適用。
- **足IKおよび膝ポールベクター**: 足IKの追従キーを適用し、膝の曲がり方向と外開きポールベクターを自動構築。
- **モーフ（ブレンドシェイプ）**: 表情キーフレームを展開。

### 4-3. カメラモーションの書き込み
全モデルのインポート完了後、カメラモーションが存在する場合は Maya シーン内に `MMD_Camera` および `MMD_Camera_Aim`（注視点ロケータ）を構築。
- `rotateOrder` を `2` (ZXY) に設定し、オイラー回転角度（X軸反転）と注視点位置、距離、画角（FOV）をキーフレーム展開。

### 4-4. BGM 音声 (.wav) のタイムライン読み込み
- Maya の `sound` ノードを生成し、WAV 音声をタイムスライダーに同期接続。
- プロジェクト全体の最大フレーム数を自動取得し、Maya のタイムライン再生範囲（0 〜 最大フレーム数、30fps NTSC）を自動構成。

## 5. モデル別VMD自動抽出および物理ベイク連携仕様

### 5-1. PMMからのモデル別VMD自動抽出・出力機構
PMMファイル内に統合保持されている各モデルのアニメーション情報（ボーン移動・回転、モーフ、IK有効フラグ）を、モデルごとに独立した標準VMDバイナリ（`.vmd`）として自動抽出し、ファイルへ保存するパイプラインを実装しています。

- **抽出バイナリフォーマット**:
  - ヘッダー署名: `Vocaloid Motion Data 0002` (30バイト)
  - モデル名: 対象モデル名称 (Shift_JIS、20バイト)
  - ボーンキーフレーム配列: 各ボーンのフレーム番号、並進ベクトル、回転クォータニオン、補間曲線を規格通りパッキング
  - モーフキーフレーム配列: 表情モーフ名、フレーム番号、ウェイト値
  - IKキーフレーム配列: IKボーンのON/OFFキーフレーム
- **出力先フォルダ構成**:
  - PMMファイルの配置場所またはプロジェクト作業領域に `pmm_vmd_data/` フォルダを自動生成。
  - モデル名に応じた `{model_name}.vmd` を書き出し、後続処理から即座に参照可能とします。

### 5-2. MayaモデルノードへのVMDパス自動記録 (`mmdVmdPath`)
インポート時に生成される各モデルのルート階層ノードに対し、抽出されたVMDファイルの所在を紐付けるメタデータ属性を自動付与します。
- **アトリビュート仕様**:
  - 属性名: `mmdVmdPath`
  - 属性型: 文字列 (`string`)
  - 値: 出力されたモデル専用VMDの絶対パス
- シーン保存（`.ma` / `.mb`）後もこの接続情報が保持され、再起動後も物理ベイク連携を維持できます。

### 5-3. 物理ベイクUI (`tab_physics.py`) とのシームレス連携
Maya側の「物理演算ベイク」タブおよび「新3D物理ビューア」との間で、手動指定を不要とする自動連携を実現しています。
- **モデル選択時の自動探索**:
  - ベイク対象モデルの選択時、ルートノード上の `mmdVmdPath` アトリビュートを自動走査。
  - アトリビュートが存在しない場合でも、`pmm_vmd_data/` 配下にモデル名と合致するVMDが存在すれば自動探索して適用。
- **UIフィードバック表示**:
  - VMDモーション情報入力欄の下部に「※pmmからインポートした場合は自動で設定されます。」の注記ラベルを表示し、ユーザーが手動でファイルを探してセットする手間を排除。
- **複数モデル順次ベイクへの自動供給**:
  - シーン内に複数モデルが存在する場合でも、各モデルの物理ベイクプロセスへ対応する専用VMDが自動的に引き渡され、個々のキャラクターに応じた独立物理ベイクが円滑に進行します。
