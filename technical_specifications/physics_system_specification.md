# Maya 物理演算システム・可視化・再吸着・ベイク技術仕様書

本ドキュメントは、「MMD Tools for Maya」における Maya シーン内での剛体・Joint可視化システム、剛体タイプ別追従階層、物理アニメーションのベイク処理、およびモデルへの自動再吸着機構に至る詳細な技術仕様を定めたものです。

---

## 1. 物理システム全体アーキテクチャ

MMD の物理演算（剛体・ジョイント）を Maya 上で直感的に扱い、ビューポート上でリアルタイム確認および高精度なアニメーション書き込み（ベイク）を行うため、以下のモジュール群で連携しています。

```text
[GUI (gui.py)]
      │
      ├──> [xpbd_visualizer.py] (Mayaコライダーメッシュ・ロケーター生成・コンストレイント管理)
      │          │
      │          └──> Maya シーンノード群 (|MMD_XPBD_VISUALIZERS)
      │
      └──> [xpbd_maya_bridge.py] (アニメーションベイク・キャッシュサンプリング制御)
                 │
                 └──> [xpbd_wrapper.py] ──> [mmd_xpbd.dll] (C++ XPBD物理エンジン)
```

## 2. 剛体・Joint可視化ノード生成仕様 (`xpbd_visualizer.py`)

### 2-1. グループ構造 (`MMD_XPBD_VISUALIZERS`)
生成される物理可視化ノードはすべて専用グループ配下に隔離され、モデル本体の階層を汚さない安全な構造になっています。

```text
|MMD_XPBD_VISUALIZERS/
├── RigidBodies/
│   ├── RB_000_頭 (球メッシュ: kinematic)
│   ├── RB_001_髪1 (カプセルメッシュ: dynamic)
│   └── RB_050_スカート1 (カプセルメッシュ: aligned)
└── Joints/
    ├── Joint_000_髪根元 (ロケーター + 軸可視化)
    └── Joint_010_スカート縦拘束
```

### 2-2. 剛体コライダーメッシュの生成
剛体の形状パラメータ（PMX仕様）に基づき、Maya のプリミティブメッシュを生成してマテリアル（半透明ワイヤー調シェーダー）を割り当てます。

- **球 (Sphere)**: 半径 $r$ に基づくポリゴンスフィア。
- **箱 (Box)**: 幅・高さ・奥行き $(w, h, d)$ に基づくキューブ。
- **カプセル (Capsule)**: 半径 $r$、長さ $h$ に基づくシリンダーと半球の結合メッシュ。

### 2-3. 剛体タイプ別追従階層とコンストレイント
MMD の剛体タイプに応じて、Maya 内での追従構造を設定します。

- **タイプ 0: Kinematic (骨追従)**
  - アニメーションボーンの動きに完全追従。
  - 親ボーンから剛体可視化ノードへ `parentConstraint` を設定。
- **タイプ 1: Dynamic (物理演算)**
  - 物理エンジンによって動かされ、結果をボーンへ書き込む剛体。
  - 初期状態では現在のボーン位置に配置され、ベイク時に物理結果に従って移動・回転。
- **タイプ 2: Aligned (位置合わせ追従)**
  - 親ボーンの平行移動には完全追従し、回転のみ物理演算を行う特殊剛体（スカートの根本や髪の根本など）。
  - 親ボーンから剛体ノードへ `pointConstraint`（位置のみ追従）を設定。

### 2-4. Joint（MMD 6DOF拘束）可視化ロケーター
- 接続剛体 A および 剛体 B の中心位置にロケーターを生成。
- ジョイントの現在姿勢（初期ポーズ時のボーン姿勢）に連動して正確なワールド座標に配置。

## 3. 物理ベイク処理仕様 (`xpbd_maya_bridge.py`)

シミュレーション結果を Maya のボーンへアニメーションキーフレーム（`animCurve`）として書き込む「ベイク」処理の技術仕様です。

### 3-1. ベイク処理の流れ
- **ステップ A: タイムライン初期化**
  - 開始フレーム（例: 0フレーム）へタイムスライダーを移動し、シーン全体の姿勢を初期化。
- **ステップ B: コンストレイント一時解除 (`mute_dynamic_constraints`)**
  - 物理剛体に設定されているボーン追従コンストレイントを一時的に `PassThrough`（無効化）に設定し、物理エンジンが自由に姿勢を制御できるように解放。
- **ステップ C: サブステップ・シミュレーション進行**
  - 各フレームごとに C++ XPBD エンジンの `step_simulation` を呼び出し。
  - キネマティック剛体（タイプ0）および位置合わせ剛体（タイプ2）の最新ボーンワールド位置を C++ エンジンへ転送。
  - C++ エンジン内で複数サブステップの物理拘束・コリジョン解決を実行。
- **ステップ D: キーフレームの書き込み**
  - 各ダイナミック剛体に対応する Maya ジョイントのローカル移動・回転アトリビュートを算出し、`setKeyframe` で記録。
  - 同時に可視化ノードの位置・回転も記録。

## 4. 剛体・Joint置き去り解消とモデル再吸着機構

### 4-1. 置き去り現象の原因分析
ベイク処理中に可視化ノード（剛体・Joint）へ記録されたキーフレームが残ったままだと、ベイク終了後にタイムラインをスクラブした際、可視化ノードが「過去にベイクされた絶対位置」に固定されてしまい、モデル本体のアニメーションから取り残されて置き去りになります。

### 4-2. 自動再吸着処理 (`reconnect_visualizers_to_bones`)
`bake_simulation` の完了時に自動的に呼び出される復元ロジックです。

```python
def reconnect_visualizers_to_bones():
    # 1. 可視化グループ配下の全ノードからベイク時のキーフレームを削除
    mc.cutKey("MMD_XPBD_VISUALIZERS", clear=True, hierarchy="below")
    
    # 2. 追従コンストレイントのミュートを解除（通常状態に復元）
    mute_dynamic_constraints(mute=False)
```

- これにより、可視化ノードが即座にモデルのボーン（物理キーが打たれた最新姿勢）へ再びぴったりと吸着し、アニメーション再生に合わせて一体となって追従するようになります。

### 4-3. 手動再吸着ボタン（GUI）
- 物理演算タブ内に「剛体・Jointをモデルに再吸着」ボタン（`btn_reconnect`）を配備。
- ベイク後やシーン編集時、いつでもワンクリックで追従状態を正常復元可能です。
